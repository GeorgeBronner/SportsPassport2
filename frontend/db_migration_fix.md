# Database migration chain is broken — diagnosis and fix

**Found:** 2026-07-23, while verifying the attendance unique-index migration on
`opencode-fixes-7-23`.
**Status: APPLIED 2026-07-23** — commit `b73cbe5`. The live database is migrated
to head with all data intact. Kept for the reasoning; the plan below is what was
implemented, with two corrections found during the work:

- **Guards live in `sports_passport/db/migration_guards.py`, not
  `alembic/guards.py`.** That directory has no `__init__.py`, so
  `from alembic.guards import ...` resolves to the *installed Alembic library*
  and raises ImportError. The plan below was wrong on this point.
- **`d1f3a7c9e5b2` also needed correcting.** It declared `sync_state.league_id`
  unique as a table constraint, while the model spells it
  `unique=True, index=True` — a unique index. Every existing database has the
  model's form (create_all built them), so a migration-built database did *not*
  match. Caught by the schema-parity test, which is why that test exists.

**Original blast radius:** `alembic upgrade head` failed from **every** database
state this project has, including a fresh one. The Dockerfile runs exactly that
command before uvicorn starts.

---

## 1. Root cause

`alembic/versions/2026_07_11_1842-9182bb4bc1d2_initial_multi_league_schema.py`
— the root revision — is an empty stub:

```python
def upgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    pass
```

The schema has therefore never been created by Alembic. It is created by
`Base.metadata.create_all(bind=engine)` at import time in `main.py:37`, with the
five later migrations `ALTER TABLE`-ing on top of whatever `create_all` had
already built.

That leaves two authorities for one schema, and they disagree:

- **`create_all` always builds the *current* models** — every table, every
  column, every index, regardless of which migrations have run.
- **Alembic's `alembic_version` records a point in a history that never
  actually created anything.**

So a migration that adds something `create_all` has already built fails with
"already exists", and on an empty database the migrations that `ALTER` a table
fail because nothing created it. Both directions are broken.

## 2. Reproduction — all four states fail

Each scenario: fresh SQLite file, schema built the way that state got its schema,
then `alembic upgrade head`.

| State | How it arises | Result |
|---|---|---|
| **A** — empty database | fresh deploy, new Docker volume | ❌ `no such table: teams` at `9182bb4bc1d2 → b4c9e1f7a2d3` |
| **B** — `create_all` schema, stamped `c8e2f4a6b1d9` | matches `backend/deploy_sports_passport.db` | ❌ `table sync_state already exists` at `c8e2f4a6b1d9 → d1f3a7c9e5b2` |
| **C** — `create_all` schema, stamped `a7e4c2f1b3d6` | **matches `backend/sports_passport.db`, the live dev database** | ❌ `table password_reset_tokens already exists` at `a7e4c2f1b3d6 → e2f5b8c3d4a1` |
| **D** — `create_all` schema, stamped `e2f5b8c3d4a1` | where production should be | ❌ `index uq_user_game_attendance already exists` at `e2f5b8c3d4a1 → f3a9d4b6c281` |

Verified 2026-07-23 by scripted runs, not by reading the code.

Two of these deserve calling out:

- **C is not hypothetical.** `backend/sports_passport.db` (149 MB, 494,320 games,
  236 attendance rows) is stamped `a7e4c2f1b3d6` while already having the
  `password_reset_tokens` table that the *next* migration wants to create. That
  database cannot be migrated today, before any of this branch's changes.
- **D is a regression introduced by this branch.** The new
  `f3a9d4b6c281` unique-index migration collides with the index `create_all`
  builds from the model's `__table_args__`. In the container it happens to
  survive first deploy — `alembic upgrade head` runs *before* uvicorn imports
  `main.py`, so on the very first boot of the new image the index does not exist
  yet — but any local database where the dev server has already booted the new
  model is stuck. This is luck of ordering, not a design that holds.

## 3. Fix

The goal is that `alembic upgrade head` **converges from any of the four states
without touching a single row of data**. Every step below is create-if-absent;
nothing drops, rewrites, or recreates a populated table.

### Step 1 — helpers for "is it already there?"

New file `backend/alembic/guards.py`:

```python
"""Schema introspection helpers for migrations.

The schema predates a working migration chain — it was built by
`Base.metadata.create_all()`, so a migration can meet a database that already
has what it intends to add. These let each step be create-if-absent, which is
what makes `upgrade head` safe to run from any historical state.
"""
import sqlalchemy as sa
from alembic import op


def _inspector() -> sa.Inspector:
    return sa.inspect(op.get_bind())


def has_table(name: str) -> bool:
    return name in _inspector().get_table_names()


def has_column(table: str, column: str) -> bool:
    if not has_table(table):
        return False
    return column in {c["name"] for c in _inspector().get_columns(table)}


def has_index(table: str, index: str) -> bool:
    if not has_table(table):
        return False
    return index in {i["name"] for i in _inspector().get_indexes(table)}
```

### Step 2 — make `9182bb4bc1d2` create the real initial schema

Fill in the stub with the six base tables **as they existed at that revision** —
that means *without* `teams.logo_url`, `venues.latitude/longitude`,
`sync_state`, `password_reset_tokens`, and without the attendance unique index,
since each of those is a later revision's job. The DDL below was taken from the
live database (`sqlite_master`), so it matches what `create_all` produces:

```python
from alembic import op
import sqlalchemy as sa

from alembic.guards import has_table

revision = '9182bb4bc1d2'
down_revision = None


def upgrade() -> None:
    # Guarded because this revision is being backfilled after the fact: every
    # existing database already has these tables, built by create_all().
    if not has_table('users'):
        op.create_table(
            'users',
            sa.Column('id', sa.Integer(), nullable=False),
            sa.Column('email', sa.String(), nullable=False),
            sa.Column('password_hash', sa.String(), nullable=False),
            sa.Column('full_name', sa.String(), nullable=False),
            sa.Column('is_admin', sa.Boolean(), nullable=False),
            sa.Column('created_at', sa.DateTime(timezone=True),
                      server_default=sa.func.now(), nullable=False),
            sa.Column('updated_at', sa.DateTime(timezone=True),
                      server_default=sa.func.now(), nullable=False),
            sa.PrimaryKeyConstraint('id'),
        )
        op.create_index('ix_users_id', 'users', ['id'])
        op.create_index('ix_users_email', 'users', ['email'], unique=True)

    if not has_table('leagues'):
        op.create_table(
            'leagues',
            sa.Column('id', sa.Integer(), nullable=False),
            sa.Column('code', sa.String(), nullable=False),
            sa.Column('name', sa.String(), nullable=False),
            sa.Column('sport', sa.String(), nullable=False),
            sa.Column('active', sa.Boolean(), nullable=False),
            sa.PrimaryKeyConstraint('id'),
        )
        op.create_index('ix_leagues_id', 'leagues', ['id'])
        op.create_index('ix_leagues_code', 'leagues', ['code'], unique=True)

    if not has_table('venues'):
        op.create_table(
            'venues',
            sa.Column('id', sa.Integer(), nullable=False),
            sa.Column('name', sa.String(), nullable=False),
            sa.Column('city', sa.String()),
            sa.Column('state', sa.String()),
            sa.Column('country', sa.String()),
            sa.Column('capacity', sa.Integer()),
            sa.Column('source', sa.String(), nullable=False),
            sa.Column('source_venue_id', sa.String()),
            sa.PrimaryKeyConstraint('id'),
            sa.UniqueConstraint('source', 'source_venue_id', name='uq_venue_source'),
        )
        for col in ('id', 'name', 'city', 'state', 'source', 'source_venue_id'):
            op.create_index(f'ix_venues_{col}', 'venues', [col])

    if not has_table('teams'):
        op.create_table(
            'teams',
            sa.Column('id', sa.Integer(), nullable=False),
            sa.Column('league_id', sa.Integer(), nullable=False),
            sa.Column('name', sa.String(), nullable=False),
            sa.Column('nickname', sa.String()),
            sa.Column('abbreviation', sa.String()),
            sa.Column('city', sa.String()),
            sa.Column('state', sa.String()),
            sa.Column('conference', sa.String()),
            sa.Column('division', sa.String()),
            sa.Column('classification', sa.String()),
            sa.Column('first_season', sa.Integer()),
            sa.Column('last_season', sa.Integer()),
            sa.Column('franchise_id', sa.Integer()),
            sa.Column('source', sa.String(), nullable=False),
            sa.Column('source_team_id', sa.String()),
            sa.ForeignKeyConstraint(['league_id'], ['leagues.id']),
            sa.PrimaryKeyConstraint('id'),
            sa.UniqueConstraint('source', 'source_team_id', name='uq_team_source'),
        )
        for col in ('id', 'league_id', 'name', 'abbreviation', 'conference',
                    'classification', 'franchise_id', 'source', 'source_team_id'):
            op.create_index(f'ix_teams_{col}', 'teams', [col])

    if not has_table('games'):
        op.create_table(
            'games',
            sa.Column('id', sa.Integer(), nullable=False),
            sa.Column('league_id', sa.Integer(), nullable=False),
            sa.Column('home_team_id', sa.Integer(), nullable=False),
            sa.Column('away_team_id', sa.Integer(), nullable=False),
            sa.Column('home_score', sa.Integer()),
            sa.Column('away_score', sa.Integer()),
            sa.Column('start_date', sa.DateTime(), nullable=False),
            sa.Column('has_time', sa.Boolean(), nullable=False),
            sa.Column('season', sa.Integer(), nullable=False),
            sa.Column('season_type', sa.String()),
            sa.Column('week', sa.Integer()),
            sa.Column('venue_id', sa.Integer()),
            sa.Column('neutral_site', sa.Boolean(), nullable=False),
            sa.Column('attendance', sa.Integer()),
            sa.Column('overtime_flag', sa.String()),
            sa.Column('source', sa.String(), nullable=False),
            sa.Column('source_game_id', sa.String(), nullable=False),
            sa.ForeignKeyConstraint(['league_id'], ['leagues.id']),
            sa.ForeignKeyConstraint(['home_team_id'], ['teams.id']),
            sa.ForeignKeyConstraint(['away_team_id'], ['teams.id']),
            sa.ForeignKeyConstraint(['venue_id'], ['venues.id']),
            sa.PrimaryKeyConstraint('id'),
            sa.UniqueConstraint('source', 'source_game_id', name='uq_game_source'),
        )
        for col in ('id', 'league_id', 'home_team_id', 'away_team_id', 'start_date',
                    'season', 'season_type', 'week', 'venue_id', 'source', 'source_game_id'):
            op.create_index(f'ix_games_{col}', 'games', [col])

    if not has_table('user_game_attendance'):
        op.create_table(
            'user_game_attendance',
            sa.Column('id', sa.Integer(), nullable=False),
            sa.Column('user_id', sa.Integer(), nullable=False),
            sa.Column('game_id', sa.Integer(), nullable=False),
            sa.Column('notes', sa.String()),
            sa.Column('created_at', sa.DateTime(timezone=True),
                      server_default=sa.func.now(), nullable=False),
            sa.Column('updated_at', sa.DateTime(timezone=True),
                      server_default=sa.func.now(), nullable=False),
            sa.ForeignKeyConstraint(['user_id'], ['users.id']),
            sa.ForeignKeyConstraint(['game_id'], ['games.id']),
            sa.PrimaryKeyConstraint('id'),
        )
        for col in ('id', 'user_id', 'game_id'):
            op.create_index(f'ix_user_game_attendance_{col}', 'user_game_attendance', [col])


def downgrade() -> None:
    for table in ('user_game_attendance', 'games', 'teams', 'venues', 'leagues', 'users'):
        op.drop_table(table)
```

> Creation order matters: `leagues` and `venues` before `teams`/`games`, `games`
> before `user_game_attendance`. SQLite tolerates forward references, PostgreSQL
> does not — get it right now rather than discovering it on a future move.

### Step 3 — guard the five existing migrations

| Revision | Change | Guard |
|---|---|---|
| `b4c9e1f7a2d3` | `teams.logo_url` | `if not has_column('teams', 'logo_url')` |
| `c8e2f4a6b1d9` | `venues.latitude` / `.longitude` | one `has_column` check each |
| `d1f3a7c9e5b2` | `sync_state` table | `if not has_table('sync_state')` |
| `a7e4c2f1b3d6` | `sync_state.last_success_at` | `if not has_column('sync_state', 'last_success_at')` |
| `e2f5b8c3d4a1` | `password_reset_tokens` table | `if not has_table('password_reset_tokens')` |
| `f3a9d4b6c281` | attendance unique index | `if not has_index('user_game_attendance', 'uq_user_game_attendance')` |

The dedupe `DELETE` in `f3a9d4b6c281` needs no guard — it keeps `MIN(id)` per
`(user_id, game_id)` and is a no-op on a database with no duplicates.

Leave the `downgrade()` bodies unguarded. A downgrade is deliberate and should
fail loudly if the thing it removes isn't there.

### Step 4 — retire `create_all()`

Only after Step 2, and as a **separate commit** so it can be reverted alone:

```python
# main.py — replace
Base.metadata.create_all(bind=engine)
with SessionLocal() as _db:
    seed_leagues(_db)

# with (migrations own the schema; seeding still belongs here)
with SessionLocal() as _db:
    seed_leagues(_db)
```

Until this lands, the two authorities keep diverging and the next model change
recreates the same class of bug. `backend/tests/conftest.py` calls `create_all`
against its own in-memory engine and is unaffected.

Local dev then requires `uv run alembic upgrade head` once before the first
`uvicorn` run — worth a line in CLAUDE.md's Common Commands.

## 4. Applying it safely

The migrations above never drop or rewrite a populated table, so the risk is
operator error, not the SQL. Still:

1. **Back up first.** WAL mode means a bare `cp` of the `.db` can miss committed
   pages sitting in the `-wal` file. Use SQLite's own backup:
   ```bash
   sqlite3 backend/sports_passport.db ".backup 'backend/sports_passport.pre-migration.db'"
   ```
   Same for the production volume, off-box.

2. **Rehearse on the copy, never the original:**
   ```bash
   cd backend
   DATABASE_URL="sqlite:///./sports_passport.pre-migration.db" uv run alembic upgrade head
   DATABASE_URL="sqlite:///./sports_passport.pre-migration.db" uv run alembic current   # expect f3a9d4b6c281
   ```

3. **Verify data survived** — counts should be identical before and after:
   ```bash
   sqlite3 backend/sports_passport.pre-migration.db \
     "PRAGMA integrity_check; PRAGMA foreign_key_check;
      SELECT (SELECT count(*) FROM games), (SELECT count(*) FROM user_game_attendance),
             (SELECT count(*) FROM teams), (SELECT count(*) FROM users);"
   ```
   Baseline as of 2026-07-23: 494,320 games / 236 attendance / 3 users.

4. **Automate the four states.** Add a test that builds each of A–D and asserts
   `upgrade head` reaches `f3a9d4b6c281`. This is the regression guard — without
   it the next stub migration reintroduces exactly this.

5. **Then production**, in this order: back up the volume → deploy → confirm the
   container passed `alembic upgrade head` → check `/health` (it now verifies
   database connectivity) → spot-check attendance counts in the UI.

## 5. Recommended sequencing

1. Guard `f3a9d4b6c281` (Step 3, last row) — smallest change, clears the
   regression this branch introduced, unblocks state D.
2. Guard the other four migrations — unblocks the live dev database (state C)
   and the deploy copy (state B).
3. Backfill `9182bb4bc1d2` — unblocks fresh deploys (state A).
4. Add the A–D convergence test.
5. Remove `create_all()`, separate commit.

Steps 1–2 are strictly additive and could ship with this branch. Steps 3–5
deserve their own branch and their own review.
